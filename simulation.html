Simulation in the browser

A desktop simulation tool, moved into the browser so the client could sell compute by the core-hour instead of licences.

  • Desktop to web
  • 3D tool interface
  • Cloud SaaS
  • Onboarding

2 min read

At a glance

Challenge

A Windows tool for specialists had to become a browser product paid by the core-hour.

Approach

Direction workshops led to one guided path from Modeler to results, plus an account portal.

Outcome

Launched publicly in 2020, from CAD to results in a browser with nothing to install.

Client
Engineering simulation startup
Role
Product designer, via studio
Year
2019–24
Platform

The problem

Where it started

  1. 01

    Every tool on screen at once

    Desktop simulators show every tool on one canvas, so newcomers could not tell which step came next.

  2. 02

    Help lived outside the product

    Learning meant leaving the model for documentation, right when someone was stuck.

  3. 03

    Cloud jobs take time and money

    Studies run for minutes or hours, billed in core-hours, so silent waits and failures cost real money.

Process

How it ran

  1. 01 Discover Workshops: who pays, who runs studies, what moves first.
  2. 02 Audit A desktop walkthrough showed where newcomers got stuck.
  3. 03 Structure Five workspaces in the order engineers think in.
  4. 04 Design & system Assistive layer, state catalogue and three view densities.
  5. 05 Ship An online library of interactive components with code.

Key decisions

Three calls that shaped it

01

Five workspaces, one path

Modeler, Physics, Simulator, Results and Export follow the order engineers already think in. A tab bar keeps the current step visible and the 3D view centred.

Details
Rejected
One canvas with every tool available at once.
Trade-off
Switching workspaces for small edits, eased with breadcrumbs and quick actions.
02

An assistive layer, not a manual

Help menus, quick guides with images, onboarding highlights and in-product feedback meet people at the step they are on.

Details
Rejected
Separate documentation outside the product.
Trade-off
More interface to keep in sync with every feature.
03

Design for waiting and failing

Simulations run for minutes or hours. Simulating, syncing, offline, errors and not enough core-hours each got an explicit state, so people always know what is happening.

Details
Rejected
Generic toasts for every situation.
Trade-off
A bigger state catalogue to maintain.

Outcome

What the team got

  • 2020 Public launch as a browser product, nothing to install
  • 5 Workspaces in one flow, from Modeler to Export
  • 0 Local installs needed to run a simulation
