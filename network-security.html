Network security console

An identity-based microsegmentation console, designed so security teams can read network policy and change it without fear.

  • Design system at scale
  • Data-dense UI
  • Network security
  • Design system

2 min read

At a glance

Challenge

Thousands of users, devices and apps had to become policies, without breaking the network.

Approach

Risk comes first, policy creation is split into guided steps, on one system with two themes.

Outcome

Shipped with risk dashboards, a guided policy builder and 20+ areas on one design system.

Client
Network security scale-up
Role
UI/UX designer, via studio
Year
2019–21
Platform

The problem

Where it started

  1. 01

    Too much data, no starting point

    The old home screen listed assets and left security leads to find the risk themselves.

  2. 02

    Policies with a large blast radius

    One wrong rule can block traffic the business depends on.

  3. 03

    Different rooms, different light

    The same screens served dark operation centres and daylight reports.

Process

How it ran

  1. 01 Discover Direct work with the client’s product team.
  2. 02 Audit Existing screens reviewed as each new area landed.
  3. 03 Structure A risk-first overview and a step-by-step policy builder.
  4. 04 Design & system One component library for dark and light themes.
  5. 05 Ship An online library with live components and code.

Key decisions

Three calls that shaped it

01

Risk before configuration

The overview opens on user, device and app risks, violations and insights. A security lead knows where to act before opening a policy.

Details
Rejected
A configuration-first home listing policies and assets.
Trade-off
More data on the first screen, held by a strict card hierarchy.
02

Build policies step by step

Add elements, define user-to-app access, set the security rule, then advanced preferences, with a preview before saving.

Details
Rejected
One long form with every option visible at once.
Trade-off
More clicks for experts, offset by direct editing of policies.
03

Two themes on one system

Teams work in dark operation centres, while reports get shared in daylight. One component library with dark and light themes covered both.

Details
Rejected
A dark-only interface.
Trade-off
Every component maintained in two themes.

Outcome

What the team got

  • 20+ Product areas designed, from overview to reports
  • 4 Steps in the guided policy builder, with a preview
  • 3 Jobs that organise every area: see risk, act, prove it
